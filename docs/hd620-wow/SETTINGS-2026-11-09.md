## Preserved starting state

Before changing any graphics setting, the saved `Config.wtf` was copied to a private timestamped backup and SHA-256 verified. A separate read-only live export recorded **278 distinct graphics-related values**, including graphics-category console CVars, graphics UI proxies and explicit renderer/window/profile controls. The full private backup is not published: it is a recovery record, not a recommended config file. Some registered names returned `nil`; those are not valid settings to restore or experiment with.

The game stayed in the same stationary outdoor view with guarded DXVK 2.7 and isolated stock Mesa 26.2.6. No shader tracing, forced SIMD, compiler experiment or hardware-policy change is involved. The effective thermal policy remains 75°C. The earlier brief 80°C attempt was aborted and is not part of these comparisons.

### Source-backed test boundaries

The [pinned graphics UI definitions](https://github.com/Gethe/wow-ui-source/blob/9dc84f0d3bbae1768ac3405b3716000bd93eda06/Interface/AddOns/Blizzard_SettingsDefinitions_Shared/Graphics.lua) define render-scale runtime bounds, manually selectable low effects options, and raw 0–9/displayed 1–10 quality sliders. The build is the Camelot flavor; live UI/readback verification is required rather than assuming Mainline behavior.

The overall quality slider is a **compound preset** with callbacks; use the actual UI and Apply. Individual graphics proxies ultimately use `SetCVar`, but their native side effects are not fully described by the public Lua source. No invented apply function, negative/editor values or rendering-work suppression is used. Projected textures/combat cues are not a preferred sacrifice for ordinary play.

No graphics candidate was applied, and no valid new baseline or comparison was completed. The saved graphics/render fields were compared with the backup afterward: **no differences in those fields**. Temporary input/screen-hold helpers were stopped; the original 75°C thermal register was independently read back again. The game process remains open at its login screen, not in-world.

The attempted baseline is explicitly rejected: no fresh engine FPS file was created, so the existing helper selected an older capture. Its timestamps exposed the stale result. The accompanying GPU stream also had only 67 valid native records against its required 68. Neither is new settings-performance evidence. Before resuming, the capture procedure must require a fresh filename/time window and visually verify in-world state before both logging commands; it must not type commands into a disconnected login screen.
